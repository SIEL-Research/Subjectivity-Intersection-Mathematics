## 1. Purpose

Experiment 002 prepares a trustworthy method for deciding whether an observed
paired-viewpoint system requires a history-bearing relational carrier.

The symbols `A` and `B` denote two operational units through which
subjectivity may function as viewpoint, projection, measurement, state, or
action. Depending on the later external test, such units may be stellar
observation-centred viewpoints, EEG channels or phase-resolved EEG measurement
processes, quantum preparation-and-measurement contexts and their recorded
event streams, or subjectivity agents with explicitly defined observation
boundaries, persistent internal states, and action channels.

This synthetic experiment does not identify any one of those units with
subjectivity itself. It calibrates a domain-neutral relational test before any
external-domain interpretation.

Its purpose is not to prove that such a carrier exists in subjectivity or in
any particular external measurement system. It asks a prior methodological
question:

> When the correct answer is known at the data-generating level, can a frozen
> analysis distinguish systems with no shared history state, systems with an
> incomplete shared history state, and systems with a pair-indexed relational
> carrier that is jointly generated and acts back upon both operational units?

The benchmark succeeds only if it detects a relational carrier when one is
needed and refuses to declare one when unit-specific memory, a common driver,
instantaneous coupling, complete history, or an incomplete shared state is
sufficient.

This is the methodological gate between the exact finite calibration in
Experiment 001 and any later application to an external observational or
interaction domain.

## 2. What the experiment can establish

A successful result will establish that the frozen discrimination procedure:

1. detects a compressed history-bearing state from noisy observable
   projections without receiving the true latent state;
2. distinguishes that state from separate unit memories and registered
   common-cause alternatives;
3. distinguishes an incomplete shared state from a pair-specific relational
   carrier;
4. preserves its decision under admissible relabelling and observation-map
   changes;
5. transfers without changing its rules to unseen histories and pairs; and
6. transfers to a second independently constructed carrier mechanism; and
7. controls false relational-carrier declarations on carrier-absent datasets.

It will not establish:

- a relational carrier in any particular external domain;
- subjectivity or intersection subjectivity;
- ontological irreducibility;
- external indescribability;
- failure of reconstruction from complete synthetic history; or
- uniqueness of one latent representation.

## 3. Registered decision problem

Each synthetic paired-unit dataset belongs to one of three target classes.

### Class 0 — No shared history-bearing state

The observed paired dependence is generated by unit-specific memory, a common
driver, instantaneous coupling, a static common object, or an observation
artifact. No independent compressed shared history state is required.

### Class 1 — Shared history state, incomplete relational carrier

A compressed shared state exists and may be history-sensitive or
intervention-sensitive, but it lacks at least one essential relational
property such as pair specificity, operational-unit-role preservation, or
bilateral feedback.

The recurrent standard full adder is the first registered Class 1 boundary
family.

### Class 2 — Pair-indexed relational carrier

A latent state `C_AB`:

- requires contributions from both operational units across its formation
  history;
- is not contained in either unit-specific state alone;
- retains compressed joint-history information;
- is indexed by the particular pair and shared history;
- affects the subsequent states or readouts of both operational units;
- responds selectively to relational intervention;
- survives admissible changes of labels and observation maps; and
- is generated by one frozen rule that transfers to new pairs.

The analysis must return both a three-class decision and a separate pass/fail
vector for the seven evidence gates. The class label must not be inferred from
one composite gate score.

## 4. Data object

The experiment uses generated paired-unit time series. It does not use
existing observational or experimental data from any external domain.

### 4.1 Latent generator state

The generator may contain:

- `M_A(t)`: unit-A-specific state or memory;
- `M_B(t)`: unit-B-specific state or memory;
- `C_AB(t)`: candidate pair-specific relational state;
- `D(t)`: optional common-driver state;
- operational-unit identity parameters;
- pair identity parameters;
- external inputs; and
- a generator-family label.

### 4.2 Observable analysis table

The frozen analysis receives only:

- opaque dataset and pair identifiers;
- time index;
- observable projections `y_A(t)` and `y_B(t)`;
- registered external inputs;
- a joint task readout;
- intervention type and timing, when applicable; and
- observation-map identifiers that do not reveal the generator family.

The analysis does not receive `M_A`, `M_B`, `C_AB`, `D`, the family label, or
the unblinding key.

### 4.3 Ground-truth table

The generator writes a separate sealed ground-truth table containing family
labels, true classes, unit identities, and pair keys. The table is used only
after the prediction and gate-decision files have been frozen and hashed.

## 5. Generator bank

All families use the same external file schema, episode lengths, identity
split, matched-condition schedule, observation maps, and noise budget.

### G0-I — Independent unit-specific memory

The A and B observable state streams are generated separately. Apparent
association arises only from matched marginal dynamics, shared task timing,
and observation noise.

Target class: 0.

### G0-C — Coupled unit-specific memories

The current A and B state streams influence one another directly in the
registered observation dynamics. No independent `C_AB` state is present.

Target class: 0.

### G0-D — History-bearing common driver

A registered external driver has an order-sensitive state and affects both
operational units. Its observable driver marker accompanies the effect. The
correct explanation is a common cause, not a state generated by the pair.

Target class: 0.

### G0-X — Instantaneous coupling

Current A and B states affect current joint output, but no state carries the
joint history forward.

Target class: 0.

### G0-H — Higher-order history without a registered low-dimensional carrier

Future joint observations depend on the registered order of the finite
formation window. Relational reset and partner substitution do not selectively
remove the effect. A finite-window history rule is therefore the registered
explanation.

This is a model-relative negative. It does not claim that no mathematical
compression can exist outside the registered model class.

Target class: 0.

### G1-F — Recurrent full-adder boundary

This family implements the standard one-bit full adder with the provisional
temporal role assignment:

- `carry_in = C_t`;
- `a = A_t`;
- `b = B_t`;
- `carry_out = C_(t+1)`; and
- `result = Y_t`.

The exact update is:

- paired input `00`: reset `C` to 0;
- paired input `01`: retain `C`;
- paired input `10`: retain `C`;
- paired input `11`: set `C` to 1.

With carry feedback, this is a two-state compressed history machine.
Reversing the order of `00` and `11` reverses the final carry state.

It is nevertheless not a complete Class 2 carrier:

- the static full-adder map is symmetric in its three inputs;
- it contains no operational-unit or pair identity;
- it does not separately update `M_A` and `M_B`;
- it does not provide bilateral unit-specific feedback; and
- complete input history reconstructs its carry exactly.

The expected benchmark decision is therefore:

- shared history state detected;
- history and intervention gates may pass;
- pair-specificity and complete relational-carrier classification fail.

Target class: 1.

This boundary family was prompted by Luke Leighton's question about whether a
standard full adder matches the proposed unit-specific-memory and relational-
state decomposition. The registered interpretation above is provisional and
does not attribute this particular role assignment to him.

### G2-P — Pair-indexed path-ordered carrier

This is the positive Class 2 family. It extends the exact path-ordered carrier
of Experiment 001 into a noisy recurrent paired-unit system.

For each pair:

1. A pair key selects a simultaneous conjugate of two fixed noncommuting
   unit actions on a four-label relational domain.
2. The hidden carrier begins at the identity and is updated by the ordered
   unit-action history.
3. Separate identity-indexed A and B base streams do not contain the complete
   interleaving.
4. Two distinct carrier probes alter the subsequent A and B observable
   readouts.
5. The observation layer exposes noisy relabelled projections of the
   unit states and joint readout, not the carrier.

The pair key changes under partner substitution. The rule that constructs the
key and carrier is unchanged across pairs.

The final registration must include the complete transition tables, pair-key
construction, probe definitions, and observation maps in executable source
before confirmatory data are generated.

Target class: 2.

### G2-M — Pair-indexed finite-matrix carrier

This is an independently constructed Class 2 transfer family. It prevents the
benchmark from succeeding merely by recognizing the surface signature of the
permutation generator.

The relational carrier is an invertible two-by-two matrix over `GF(3)`.
Unit A and unit B contribute two fixed noncommuting elementary
matrices. A pair-specific invertible matrix simultaneously conjugates both
unit actions, and the hidden carrier is updated by their path-ordered
matrix product.

Two different carrier probes act upon the separate A and B readout streams.
Observed outputs are noisy categorical projections of those streams and
probes, not entries of the carrier matrix.

The complete transition, conjugation, probe, feedback, and observation rules
must be implemented and hashed in the final registration before confirmatory
data are generated.

G2-M is excluded from the design of classifier thresholds and rules. It is
used only as the registered second-mechanism transfer target.

Target class: 2.

## 6. Required matched counterfactuals

Every Class 2 dataset includes generator-level matched counterfactual episodes.

### C-only contrast

`M_A`, `M_B`, external inputs, and observation conditions are held fixed while
`C_AB` is changed. Both carrier states must be reachable under valid registered
histories; arbitrary off-manifold latent replacement is not permitted. The
preregistered future readout must change.

### Partner-substitution contrast

One operational unit is replaced while unit-level distributions are matched.
The pair-indexed state must change according to the frozen pair-generation
rule.

### Relational-reset contrast

The carrier or its operational realization is reset without applying a
general task reset. Subsequent joint dynamics must change in the preregistered
direction.

Equivalent interventions are applied to Class 0 and Class 1 families wherever
the target exists. The analysis must not report an unavailable intervention
as evidence for a carrier.

## 7. Observation and noise conditions

Each dataset contains 16 matched counterfactual repetitions rendered through
four fixed bijective permutations of the three observable labels. The
repetitions cover categorical corruption probabilities `0.00`, `0.05`,
`0.10`, and `0.20`, with missing-observation probabilities `0.00` and `0.05`.

Admissible gauge transformations are bijective transformations of labels and
registered coordinates. Noninvertible projections and added noise are
reported separately as observation degradation, not called gauges.

## 8. Identity, pair, and episode splits

Each generator family uses the same split template:

- 16 seen operational-unit identities;
- 8 completely held-out operational-unit identities;
- 8 registered pairs among seen identities;
- 8 unseen recombinations of seen identities; and
- 4 pairs formed only from held-out identities.

Each family-pair dataset contains 16 repetitions of six matched conditions,
with 32 transitions per condition. T1 uses new histories for the eight
registered pairs, T2 uses the eight unseen recombinations, and T3 uses the
four pairs formed only from held-out identities.

The generator-family counts are balanced within every transfer level and noise
condition.

The final generation script must reject identity or pair overlap that violates
the registered split.

## 9. Frozen discriminator

The confirmatory analysis contains no fitted classifier. For each opaque
dataset and observation map it computes label-invariant categorical mismatch
rates between matched reference, history, reset, partner-substitution,
remove-A, and remove-B conditions.

The registered decision uses:

- a history mismatch threshold of `0.58`;
- matched reset, partner, remove-A, and remove-B margins of `0.25`;
- bilateral A/B history mismatch at `0.58`;
- explicit common-driver separation; and
- gauge-decision consistency of at least `0.95`.

Class 2 requires joint generation, history dependence, selective reset,
pair specificity, bilateral feedback, null separation, gauge invariance, and
frozen transfer. Class 1 requires history dependence and selective reset but
fails at least one complete-carrier condition. All remaining datasets are
Class 0.

The analysis receives no generator family, true class, operational-unit
identity, pair key, or latent state.

## 10. Frozen analysis outputs

For every opaque dataset, the analysis writes:

- predicted class `0`, `1`, or `2`;
- pass/fail decision for each evidence gate;
- label-invariant history and bilateral mismatch rates;
- reset, partner, remove-A, and remove-B margins;
- common-driver separation;
- T1, T2, and T3 transfer scores;
- second-mechanism transfer score on G2-M;
- gauge-consistency score;
- family-level recall after unblinding; and
- the false Class 2 declaration rate.

The prediction file is hashed before ground truth is unsealed.

## 11. Operational evidence-gate tests

### J — Joint generation

Removing either unit's contribution from the registered formation period must
disrupt the Class 2 readout relative to the matched reference.

### H — History irreducibility

Under matched current observable and unit-specific memory states, differing joint
histories must predict different futures on Class 2 data.

### I — Intervention sensitivity

The relational reset and C-only counterfactual must change future joint
dynamics in the registered direction. General performance degradation alone
does not pass this gate.

### P — Pair specificity

Partner substitution or history reassignment must change the inferred state
for Class 2. G1-F is expected not to pass this gate.

### G — Gauge invariance

Class and gate decisions must remain unchanged under registered bijective
relabelings. Performance degradation under noninvertible observation loss is
reported separately.

### N — Null-model separation

Class 2 must be separated from every Class 0 family and from the Class 1
boundary. The analysis must also select the appropriate registered
alternative on Class 0 datasets.

### T — Frozen transfer

The unchanged pipeline, thresholds, and gate definitions must be applied to
T1, T2, and T3. The same fixed rules must also be applied to the G2-M
second-mechanism transfer.

## 12. Primary and secondary endpoints

### Primary endpoint

Three-class balanced accuracy on the sealed T1, T2, and T3 datasets, together
with the false Class 2 declaration rate on true Class 0 and Class 1 datasets.

### Required primary acceptance targets

All of the following are required:

- balanced accuracy at least `0.80` at each of T1, T2, and T3;
- recall at least `0.70` for each class at each transfer level;
- false Class 2 declaration rate at most `0.10` on the combined true Class 0
  and Class 1 datasets;
- Class 2 recall at least `0.80` on G2-P; and
- Class 2 recall at least `0.70` on the independently constructed G2-M
  second-mechanism transfer; and
- unchanged class decision in at least `0.95` of registered gauge replicas.

These are benchmark acceptance thresholds, not estimates of external-domain
effect size.

### Secondary endpoints

- gate-specific precision and recall;
- registered mismatch and counterfactual margins;
- family-level recall;
- gauge consistency; and
- transfer-level confusion matrices.

No secondary endpoint can rescue a failed primary endpoint.

## 14. Falsification conditions

Experiment 002 is not supported if any required primary acceptance target
fails.

Particular failure modes include:

- the procedure calls G1-F a complete Class 2 carrier;
- Class 0 common-driver data are repeatedly classified as Class 2;
- the Class 2 decision depends on coordinate labels;
- partner substitution leaves the G2-P carrier decision unchanged;
- T1 succeeds but T2 or T3 fails after freezing; or
- the relational decision succeeds on G2-P but fails the registered G2-M
  second-mechanism transfer; or
- unblinding occurs before prediction hashes are fixed.

## 15. Interpretation ladder

Results are reported in this order:

1. **Computed benchmark result:** classification, gate, intervention-margin,
   gauge, and transfer scores.
2. **Methodological interpretation:** whether the frozen procedure
   discriminates the three registered synthetic classes.
3. **Operational carrier conclusion:** whether Class 2 can be identified under
   the registered observation conditions.
4. **External boundary:** no inference to a relational carrier in any
   external measurement system, and no identification of an operational unit
   or carrier with subjectivity itself.

The phrase “relational carrier detected” applies only to the registered
synthetic class unless and until the unchanged method is tested on an external
system.
