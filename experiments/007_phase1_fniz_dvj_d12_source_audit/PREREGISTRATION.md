# Preregistration: Experiment 007 Phase 1

## Title

Source-Derivation Audit for a Composite FNIZ-DVJ-D12 Operational Carrier Candidate

## Registration status

Preregistered before execution of the frozen Phase 1 runner.

## Research question

Do the frozen D12RG Riemann and Advaita sources uniquely determine an executable connector from signed FNIZ operation history, through the native DVJ transfer, to a moving D12 deck action?

## Role within Experiment 007

Experiment 007 is divided into three non-interchangeable phases:

1. Phase 1: source-derivation audit;
2. Phase 2: finite candidate search, only if Phase 1 does not yield a unique rule;
3. Phase 3: held-out confirmation of one frozen rule, only after the search record has been separately published.

Each phase requires its own frozen public record. A rule selected in Phase 2 remains a constructed bridge even if it later passes held-out tests. It must not be redescribed as source-derived.

This preregistration covers Phase 1 only.

## Primary object and ontological boundary

The cross-layer object under investigation is provisionally denoted `K^E_FNIZ-DVJ-D12`. It is a composite operational Class 2 carrier candidate.

It is not denoted `O3_E` in this phase. A candidate operational projection of O3 would require, beyond the composite connector audited here:

- a distinct persistent self-state;
- an internally mediated update not reducible to a readout label;
- measurable return action to both A and B; and
- survival of matched alternative explanations.

No Phase 1 outcome validates SIO, establishes subjectivity, proves ontological non-reducibility, or proves the Riemann hypothesis.

## Registered source claims to audit

### S1. Signed FNIZ carrier

The Riemann source defines eight oriented states and keeps positive and negative zero distinct.

### S2. Four operations

The operation family is exactly addition, subtraction, multiplication, and division.

### S3. Primitive-versus-derived operation hypothesis

The following is tested rather than assumed:

- subtraction equals addition after orientation reversal of the right operand;
- division equals multiplication by the formal reciprocal of the right operand.

Passing these finite identities establishes an algebraic derivation in the signed packet calculus. It does not establish that subtraction or division is generated by mathematical integration. An integration-specific claim counts as source-supported only if an explicit frozen source statement or executable identity is found.

### S4. D12 group and Lagrange constraint

The deck translations are audited as the cyclic action of order twelve. For every generated subgroup, its order must divide twelve. This is a conditional constraint on deck actions. It does not establish that the composite FNIZ-DVJ-D12 carrier itself is a group.

### S5. Native DVJ-to-D12 compatibility

The native DVJ transfer must be nonzero on the registered finite probes, must define reciprocal forward and inverse factors, and must close as the central holonomy of the frozen twelve-step clock.

### S6. Source-defined connector

The frozen source tree is searched for an executable definition that jointly consumes or references:

- signed FNIZ state or operation history;
- native DVJ transfer or holonomy; and
- a D12 deck step or moving projector.

Documentation language alone is recorded separately from an executable cross-layer mapping.

## Conditional candidate family

If the sources establish the primitive/derived identities but provide no operation-to-deck anchor, the audit will enumerate the full conditional family in which:

- addition is assigned an arbitrary element `a` of C12;
- multiplication is assigned an arbitrary element `m` of C12;
- subtraction is assigned `-a mod 12`;
- division is assigned `-m mod 12`.

This family contains 144 rules before any additional source constraint. It is an audit of residual underdetermination, not a confirmatory search space and not evidence that any member is correct.

The audit will report the pruning power of every registered constraint. It will not select one of the residual rules.

## Primary classification

Exactly one of the following classifications will be reported:

- `UNIQUE_SOURCE_DERIVED_RULE`: one executable connector is explicitly determined by the frozen sources;
- `MULTIPLE_SOURCE_ADMISSIBLE_RULES`: more than one executable connector remains after all explicit source constraints;
- `SOURCE_CONSTRAINTS_DO_NOT_NARROW`: the audited constraints do not reduce the registered conditional family;
- `NO_ADMISSIBLE_RULE`: explicit source constraints are mutually incompatible within the registered family;
- `INCOMPLETE_SOURCE_DEFINITION`: one or more premises needed to define the connector are absent, so no rule can be called source-derived.

`UNIQUE_SOURCE_DERIVED_RULE` requires an explicit executable cross-layer mapping or a derivation whose premises and unique solution are all present in the frozen sources. Merely routing an FNIZ value into a selector in new code is true by construction and cannot satisfy this criterion.

## Completion criteria

Phase 1 is complete only if all of the following are true:

1. both source authorities pass exact provenance checks;
2. every required source file passes SHA-256 verification;
3. the signed-FNIZ state and operation audits execute;
4. primitive-versus-derived identities are evaluated over all 64 ordered signed-state pairs;
5. the D12 group and subgroup-order audits execute;
6. the registered DVJ probes pass numerical source checks;
7. the source-defined connector search executes over the frozen source tree;
8. residual candidate count and pruning power are reported without selection; and
9. one primary classification is emitted.

The classification itself is not required to be positive. Provenance failure or an incomplete audit is an execution failure; source underdetermination is a valid scientific result.

## Downstream firewall

No Phase 2 search may begin until the Phase 1 result is published as a separate immutable record.

If Phase 2 is required, its complete source-admissible candidate family, scoring rule, tie rule, and all inspected data must be frozen before search. If no defensible source pruning exists, the full registered family must be used.

Any later Phase 3 confirmation must include an equally expressive factorised null with the same product, quotient, sign, deck, holonomy, and memory operations but without the proposed relational temporal correspondence. Confirmatory evidence must rest on held-out correspondences, recursive closure, matched cross-pair interventions, downstream bilateral effects, and failure of equally simple alternative mappings. By-construction routing is not confirmatory evidence.
