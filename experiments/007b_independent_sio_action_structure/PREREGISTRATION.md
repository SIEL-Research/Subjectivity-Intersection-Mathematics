# Preregistration: Experiment 007B

## Title

Independent Construction of the SIO Action Structure from Frozen 006-Series Experiments

## Status

Preregistered and not executed at the time of registration.

This experiment is result-informed by Experiments 006, 006R, 006A, and 007A, and by the subsequent methodological discussion with Luke Leighton, C.A.T., Marcel Wende, and Thomas Loker. It is not a blind discovery study. Its purpose is to construct the SIO-side action object without using D12RG as a target.

## Primary question

What typed mathematical action structure is generated by the implemented relational-state transformations already frozen in Experiments 006, 006R, and 006A?

Experiment 007B does not test any D12RG occurrence of the number seven, does not attempt to derive the D12RG equations, and does not require a closed normalized algebra. D12RG source files, tables, dimensions, generators, and invariants are excluded from the runner.

## Revision record

An earlier planning draft named seven semantic operation families. Thomas Loker identified that this could anchor the primitive count to a known downstream comparison object. Marcel Wende clarified that semantic families are not mathematical primitives: one family may contain several typed actions and several labels may canonicalize to one action.

The operative extraction below therefore contains no cardinality target. The earlier list is retained only in this revision record and has no role in candidate extraction, canonicalization, classification, or acceptance.

## Frozen sources

The runner verifies SHA-256 digests for the public preregistrations, technical specifications, runners, registration manifests, result summaries, and executable dependencies of:

- Experiment 006;
- Experiment 006R; and
- Experiment 006A.

Experiment 006R reuses the Experiment 006 computation and contributes no new relational-state transformation. That absence is recorded rather than filled by inference.

## Inclusion rule for operation sites

An operation site is included only when all of the following hold:

1. it occurs in the frozen executed runner or an executable dependency actually called by that runner;
2. it has an explicitly identifiable typed input and output;
3. it constructs, transforms, routes, replaces, advances, or reads a relational component or ordered A-B state; and
4. its source function and required source fragments are frozen in `source_action_registry.json`.

The inventory excludes optimization, initialization, random-number generation, file input/output, logging, aggregation, plotting, threshold decisions, and controls that only generate comparison directions.

Code that was merely present in a frozen dependency but was not called by the 006-series runners does not enter the base action set. In particular, no temporal-reversal action, CDC 6600 action, D12RG action, or retrospectively proposed action is imported.

## Two-stage extraction

### Stage 1: source-supported operation-site inventory

Every registered operation site is verified against its exact source function and frozen source fragments. Multiple sites may support the same mathematical action.

### Stage 2: preregistered canonicalization

Sites are canonicalized by the tuple:

`(canonical rule, ordered input types, output type, linearity class, direction metadata)`.

Names and prose descriptions do not determine equivalence. The ordering of A and B, receiver direction, pair routing, and historical direction are preserved. Two sites with the same tuple become one primitive action. Sites with different tuples remain distinct even when they share a semantic label.

## Registered base actions

The registry is source-derived and contains no target count. It covers:

- time-indexed extraction of a state bundle;
- receiver-directed relational-component extraction;
- inclusion-exclusion relational-component extraction;
- relational-component erasure from the joint state;
- substitution of a donor relational component;
- recurrent state advance;
- replacement of the joint member in a counterfactual state bundle;
- suffix continuation and behavioral readout;
- cross-pair donor routing;
- donor-index permutation of a relational component; and
- subtraction of counterfactual relational components to obtain the transported contribution.

The actual primitive count is produced only after canonicalization.

## Carrier and scalar declaration

The frozen computational carrier uses real-valued arrays. Types distinguish at least:

- ordered counterfactual state bundles;
- joint hidden states;
- relational components;
- input steps and suffix sequences;
- pair-label arrays and donor permutations;
- model parameters; and
- bilateral logits.

The scalar domain is therefore the real numbers for the executable witness. The runner separately identifies actions that are linear over the real product space, actions that are affine, and actions that are nonlinear. It does not infer a rational, complex, or other scalar structure.

## Common-carrier and closure test

The runner asks whether all canonical primitives are linear endomorphisms of one common carrier. A complete multiplication table is computed only if this condition is satisfied and finite closure is established by the registered procedure.

If the actions have different typed domains or codomains, or if recurrent `tanh` dynamics are required, the result is recorded as a typed nonlinear action structure. It is not forced into an operator algebra.

## Composition structure

Composition is defined only when the output type of one action matches an input type of another action. The runner writes the complete registered typed-composability table.

The principal source-supported mediation route is:

state bundle -> relational component -> intervened joint state -> recurrently advanced joint state -> updated state bundle -> next relational component.

Behavioral continuation from an intervened or advanced joint state to bilateral logits is recorded separately.

## Exact witness tests

Deterministic synthetic witness arrays are used only to test mathematical properties of the frozen transformations; no trained result is re-estimated.

The witness tests verify:

- linearity of the two extraction maps;
- non-equivalence of receiver-directed and inclusion-exclusion extraction on at least one frozen witness;
- exact erasure and donor-substitution identities;
- nonlinearity of recurrent advance caused by `tanh`;
- typed recurrent mediation from current relation to next relation;
- absence of a source-defined canonical global generator or involution; and
- absence of a common linear-endomorphism carrier for all primitives.

## Robustness analyses

The runner reports, without changing the primary decision:

1. one-primitive-removed classifications for every canonical primitive;
2. which primitives are critical to the registered relational mediation route; and
3. one predeclared addition variant using the ordered receiver partition already executed by the frozen sources.

The addition candidate is fixed before execution and cannot be replaced after inspection.

## DJS hypergroup boundary

A Dunkl-Jewett-Spector hypergroup is preregistered as a comparison candidate, not as the null floor.

It may be reclassified as the minimal null only if the frozen SIO assumptions force, without additional modelling choices:

- a base space `K`;
- an associative convolution of point masses into compactly supported probability measures;
- an identity;
- an involution; and
- the required support and continuity conditions.

If any item is absent or introduced by modelling choice, DJS remains a comparator. A bare inverse or reversal does not by itself force a Chebyshev recurrence, an SL2 trace algebra, or the specialization `E^2 + Q^2 = 4`.

## Primary classifications

Exactly one completed-run classification is emitted:

- `STABLE_FINITE_DIMENSIONAL_LINEAR_ACTION_ALGEBRA`
- `STABLE_LINEAR_ACTION_STRUCTURE_WITHOUT_FINITE_CLOSURE`
- `STABLE_NONLINEAR_OR_TYPED_ACTION_STRUCTURE`
- `MULTIPLE_NON_EQUIVALENT_ACTION_STRUCTURES`
- `NO_STABLE_ACTION_STRUCTURE`
- `PROVENANCE_FAILURE`

`PROVENANCE_FAILURE` terminates the scientific classification.

## Stability rule

A structure is stable when:

1. every primitive has at least one verified frozen source site;
2. canonicalization is deterministic and unique;
3. the typed composition table is complete for the registered primitives;
4. the primary structural class is unchanged in every one-primitive-removed variant and in the predeclared addition variant; and
5. no unregistered semantic choice is needed to select among multiple non-equivalent canonicalizations.

Essentiality of a primitive to the mediation route is reported separately and does not by itself make the canonicalization unstable.

## Interpretation boundary

The experiment constructs an operational SIO-side action object from prior computational experiments. It does not establish phenomenal subjectivity, ontological O3, a D12RG isomorphism, a DJS hypergroup, or a new abstract algebra.

Any later SIO-D12RG comparison belongs to Experiment 007C. If the D12RG target is not frozen before the 007B result is known, that comparison must be labeled a source-constrained post-result construction rather than a blind convergence test.
